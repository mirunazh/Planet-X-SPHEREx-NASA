- Minimal parser alternative: a SPHEREx cutout is a MEF; plain IMAGE HDU is raw big-endian float32 after 2880-byte header blocks, readable with ~40 lines of JS (DataView, `getFloat32(i*4,false)`), header cards 80 chars. UNVERIFIED for cutouts (IMAGE is uncompressed per context file).
- Pyodide 314.0.8 (MPL-2.0, published 2026-11-13) on jsDelivr: astropy 7.2.0 in the lock file (needs numpy 2.4.6, pyerfa, astropy_iers_data); `pyodide.asm.wasm` 9.6 MB, `python_stdlib.zip` 2.5 MB, plus numpy and astropy wheels (tens of MB; astropy wheel size not measured). `reproject` NOT in the lock file (so no browser reproject). Cold load realistically several seconds to tens of seconds: UNVERIFIED timing. VERIFIED: https://cdn.jsdelivr.net/npm/pyodide@314.0.8/pyodide-lock.json
- Rendering float32 to canvas: asinh stretch `v = asinh((x-lo)/s)/asinh((hi-lo)/s)`; zscale via sort of a subsample (~1000 px) and linear fit, or use percentile clip (1st to 99.5th). 2D canvas via `ImageData` (fast enough for 2040x2040 or small cutouts); WebGL via `texImage2D(gl.R32F)` with `OES_texture_float_linear` is optional and lets stretch/colormap be uniforms with instant slider response. All math is trivial, no library needed. UNVERIFIED snippets are standard practice.

```js
// asinh stretch of float32 array to canvas (grayscale)
function draw(canvas, data, w, h, lo, hi, soft=(hi-lo)/10){
  const ctx=canvas.getContext('2d'), im=ctx.createImageData(w,h), n=Math.asinh((hi-lo)/soft);
  for(let i=0;i<w*h;i++){const v=data[i]; const t=isFinite(v)?Math.max(0,Math.min(1,Math.asinh((v-lo)/soft)/n)):0;
    const g=255*t; im.data.set([g,g,g,255],4*i);}
  canvas.width=w;canvas.height=h;ctx.putImageData(im,0,0);}
```

## Implications for the viewer (opinions)

Ranked architectures:

1. Static front end (canvas player) + tiny CORS proxy (Cloudflare Worker) + IRSA server-side cutouts. Page takes `?ra=&dec=&fov=`; Worker proxies IRSA TAP (cutout list) and cutout FITS (IRSA sends no CORS, 503 retry-after seen, so Worker retries); browser parses plain IMAGE HDU (own parser or fitsjs-ng), asinh/zscale on canvas, plays frames sorted by `time_bounds_lower`, per-detector D1..D6 filter, add/subtract in JS, Gaia/CatWISE overlay via the proxy with PM propagation, SkyBoT directly (CORS yes), hips2fits or Legacy cutout.jpg/fits for backdrop (Legacy CORS yes). Best weekend fit: no Python hosting, instant interactivity. Risk: Worker CPU limits, IRSA load.
2. Aladin Lite as the base map plus the same frame player. Use Aladin for the sky background (DSS/WISE HiPS), the 102-band SPHEREx cube HiPS (`setSliceNumber`, CORS ok, likely loads directly, needs a 5-minute browser test), Gaia via `catalogFromVizieR` and PM vectors via `A.vector`; per-epoch frames as `imageFITS` layers or a custom canvas. Strongest for "overlay" and "creative 102 bands" but no timeline; LGPL fine for a web page.
3. FastAPI backend (astropy, reproject) rendering PNG/WebP frames, deployed on Cloud Run or Lambda us-east-1 near the bucket. Most capable (reproject to common WCS for true blink alignment, stacking, spectra extraction, flag masks), best data correctness, but costs ops time, cold starts, and needs caching; frame stacks are heavy. Use if frames must be WCS-aligned across detectors.
4. Firefly embed (irsa loader or firefly_client in a notebook). Gives blink, WCS-lock, flags, spectra for free but UX and embeddability are not ours; fine as a demo fallback or "open in IRSA" link.
5. Pyodide+astropy in browser: possible (astropy 7.2.0 wheel in Pyodide 314.0.8) but heavy download, no reproject, slow start; reject.
